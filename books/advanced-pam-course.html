Why this book?

The problem

PAM decides who gets into a Linux system, and it is easy to configure by copying snippets without knowing what each line does. One wrong line can lock you out of the machine, or let in a login that should have failed.

The solution

The book starts from the PAM architecture and works up, chapter by chapter, to:

  • Password policy and account lockout with pam_pwquality and pam_faillock
  • Central accounts with SSSD, LDAP, Active Directory and smartcards
  • A second factor with U2F, FIDO2 and TOTP, for local login and for SSH
  • Ansible roles tested with Molecule
  • Writing a PAM module in C

Compliance is covered by topic: PCI DSS, NIST SP 800-53, SOC 2, ISO 27001 and the CIS Benchmarks.

What is in the book

  • Hands-on labs

    Nine labs, each tied to a chapter. They are meant for virtual machines, never for a production host.

  • Tested configurations

    The labs and every printed configuration were run in containers of AlmaLinux 9.8, Rocky Linux 9.8, Ubuntu 24.04 and Debian 13.

  • Not tested

    Anything that needs a physical FIDO2 key, SELinux in enforcing mode or a real Active Directory join.

  • Two distribution families

    The RHEL family with authselect, Debian and Ubuntu with pam-auth-update. Chapter 11 is the Debian and Ubuntu guide.

  • Automation

    Ansible roles for password quality and account lockout, tested with Molecule.

  • Case studies

    Three real incidents: GitLab (2017), Code Spaces (2014) and Equifax (2017).

  • Legibility

    The interior is set in Atkinson Hyperlegible. The layout aims for legibility, including for neurodivergent readers.

Frequently asked questions

  • Do I need prior PAM experience?

    No. Chapter 1 starts from the PAM architecture. The book assumes basic Linux and command-line knowledge.

  • Which Linux distributions are covered?

    The RHEL family and Debian/Ubuntu. The labs and the printed configurations were run on AlmaLinux 9.8, Rocky Linux 9.8, Ubuntu 24.04 and Debian 13, in containers.

  • Do I need a YubiKey to follow the labs?

    Only for Lab 6.1, which asks for a physical YubiKey. Lab 6.2 sets up SSH with a public key, a password and TOTP, and needs no hardware key.

  • What was not tested?

    Anything that needs a physical FIDO2 key, SELinux in enforcing mode or a real Active Directory join.

  • Which languages will it be in?

    Spanish first, then English, then Brazilian Portuguese. It is the same book in each language: one edition, with no tiers and no bundles.

  • When will it be out?

    No release date has been announced. The waitlist gets a message when the book is out.
